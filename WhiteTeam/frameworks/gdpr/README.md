# GDPR Framework Reference

## Overview

The General Data Protection Regulation (GDPR) is a regulation in EU law on data protection and privacy for all individuals within the European Union and the European Economic Area.

## Key Principles (Article 5)

| Principle | Description |
|-----------|-------------|
| Lawfulness, Fairness, Transparency | Process data lawfully and transparently |
| Purpose Limitation | Collect for specified, explicit purposes |
| Data Minimization | Adequate, relevant, limited to necessary |
| Accuracy | Keep data accurate and up to date |
| Storage Limitation | Keep only as long as necessary |
| Integrity and Confidentiality | Ensure appropriate security |
| Accountability | Demonstrate compliance |

## Lawful Bases (Article 6)

1. **Consent** - Freely given, specific, informed
2. **Contract** - Necessary for contract performance
3. **Legal Obligation** - Required by law
4. **Vital Interests** - Protect someone's life
5. **Public Task** - Official authority or public interest
6. **Legitimate Interests** - Balanced against individual rights

## Data Subject Rights

| Right | Article | Description |
|-------|---------|-------------|
| Information | 13-14 | Right to be informed |
| Access | 15 | Right to access data |
| Rectification | 16 | Right to correct data |
| Erasure | 17 | Right to be forgotten |
| Restriction | 18 | Right to restrict processing |
| Portability | 20 | Right to data portability |
| Object | 21 | Right to object |
| Automated Decisions | 22 | Rights related to profiling |

## Key Requirements

### Data Protection by Design (Article 25)

- Implement appropriate measures
- Pseudonymization
- Data minimization
- Default privacy settings

### Security (Article 32)

- Encryption
- Confidentiality
- Integrity
- Availability
- Resilience
- Regular testing

### Breach Notification

| Notification | Timeline | Recipient |
|--------------|----------|-----------|
| Authority | 72 hours | Supervisory authority |
| Data Subjects | Without undue delay | Affected individuals |

### DPIA Requirements (Article 35)

Required when processing likely results in high risk:
- Systematic evaluation of personal aspects
- Large-scale processing of special categories
- Systematic monitoring of public areas

## Roles

| Role | Responsibility |
|------|----------------|
| Data Controller | Determines purposes and means |
| Data Processor | Processes on behalf of controller |
| DPO | Oversees compliance |
| Supervisory Authority | Enforces regulation |

## Penalties

| Tier | Maximum Fine | Violations |
|------|--------------|------------|
| Lower | €10M or 2% revenue | Technical violations |
| Upper | €20M or 4% revenue | Core principles violations |

## Documentation Requirements

- Records of processing activities
- Data protection policies
- Privacy notices
- Consent records
- DPIA documentation
- Data breach register
- Data processing agreements
